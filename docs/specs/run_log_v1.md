# Run log schema v1

The local implementation writes to `outputs/runs/runs.sqlite`. It creates the following
tables: `runs`, `node_events`, `decisions`, `sql_attempts`, and `artifacts`. Every run is
written in one SQLite transaction. If a write fails, a minimal JSON failure record is placed
under `outputs/runs/failed/`; the caller should preserve the agent result and report the
logging failure separately.

The schema contains `runs`, `node_events`, `llm_calls`, `decisions`, `retrievals`,
`sql_attempts`, `checks`, `artifacts`, `evidence`, `data_requests`, `feedback` and `memory`.
The schema deliberately excludes API keys, IP addresses and account identifiers. Store only
the question, run/conversation IDs generated by the application, configuration metadata,
node events, decisions, SQL attempts and evidence needed for evaluation.

Export:
`python -m analyst.ops.export_runs --db outputs/runs/runs.sqlite --out bundles/member_YYYYMMDD-HHMM/`

The exporter writes one Parquet file per table and `manifest.json` with row counts, SHA-256
checksums, schema version and Git SHA. This initial local SQLite schema is a development
implementation; reconcile table names and columns with the team's frozen Section 9 schema
before merging with T4's collator.
